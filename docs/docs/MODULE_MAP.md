# Druid Engine — Module Map (Stage 0)

Generated by structural walk only (filenames, line counts, grep of signatures and
`#include` lines). No file bodies were read; purpose lines are inferences.

**Repo layout:** C11 engine core built as `druid` shared lib (`src/` + single
public header `include/druid.h`), C++17 ImGui editor (`Editor/`), C++ testbed
app (`testbed/`), vendored third-party in `deps/`, `include/{assimp,GL,SDL3}`,
`src/external/`, `Editor/deps/`.

**Key structural fact:** every engine `.c` file includes only `include/druid.h`
(2,295 lines — the entire public+internal API surface: ~130 typedefs, ~505
function declarations) plus libc/system headers. There are no per-module
headers; all cross-module dependency flows through this one monolithic header.

**Line counts:** engine core `src/` ≈ 13,355 (excl. vendored stb_image),
`druid.h` 2,295, Editor sources ≈ 9,830, testbed 70. Total first-party ≈ 25,800.

## Proposed Stage 1 dispatch plan (dependency-ordered)

Each row = one `module-doc-writer` dispatch. Leaf/foundation modules first so
later dispatches can assume their docs. Every dispatch should also read the
relevant section of `include/druid.h` for its structs (it's the only header).

**Wave 1 — foundations (parallel):**
1. `core-memory` — vmem.c, arena.c, buffer.c, hashmap.c (+druid.h memory section)
2. `core-math` — math.c, simd.c, transform.c (+druid.h math types)
3. `core-platform` — platform.c, file.c, dllloader.c, logging.c, profiler.c
4. `core-input` — input.c (+druid.h KeyCode/ControllerCode)

**Wave 2 — mid-layer (parallel, assume Wave 1 docs):**
5. `asset-loading` — resourcemanager.c, objloader.c
6. `rendering-buffers` — framebuffer.c, gbuffer.c, geometrybuffer.c, instancebuffer.c, indirectbuffer.c, modelssbo.c, ssbo.c, ubo.c
7. `rendering-primitives` — shader.c, texture.c, camera.c, display.c, gizmo.c
8. `ecs-storage` — archetype.c, entityarena.c (+druid.h Archetype/EntityArena/StructLayout)
9. `mesh-model-material` — mesh.c, model.c, material.c

**Wave 3 — systems (parallel, assume Waves 1–2):**
10. `ecs-scene-prefab-systems` — scene.c, prefab.c, ecssystem.c
11. `renderer` — renderer.c (large, alone)
12. `physics-world` — physics.c (large, alone)
13. `physics-shapes` — collider.c, contact.c, narrowphase.c, broadphase.c, rigidbody.c
14. `audio` — audio.c

**Wave 4 — top layer (parallel, assume all above):**
15. `application-runtime` — application.c, runtime.c (+druid.h Application/GameRuntime/RuntimeConfig)
16. `build-system-testbed` — CMakeLists ×3, generate_msvc\*, druid_msvc.def, testbed/src/main.cpp

**Wave 5 — editor (parallel, assume engine docs):**
17. `editor-core` — Editor/src/main.cpp, editor.h, hub.cpp/h, entitypicker.cpp/h
18. `editor-ui-1` — editor.cpp: viewport/render path (renderGameScene, FBOs, skybox, camera, entity picking glue, uploadSceneLights, snapshot/restore, doBuildAndRun)
19. `editor-ui-2` — editor.cpp: panels (inspector/SoA editor, archetypes, prefabs, scenes, resource manager tabs, profiler, console, build log)
20. `editor-project-builder` — project_builder.cpp/h

20 dispatches total. druid.h has no dedicated dispatch — each module doc covers
its own druid.h section; `application-runtime` (15) should flag any druid.h
declarations no module claimed.
